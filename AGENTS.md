# Cirrus

TanStack Start (React) app and an Effect API on Cloudflare Workers, deployed with Alchemy v2.

## Layout

- `alchemy.run.ts` is the Alchemy Stack. It declares the `Web` Worker, a `Cloudflare.Website.Vite` site whose entry is TanStack Start's SSR bundle, and binds the `Api` Worker into it as `env.API`.
- `worker/api.ts` is the API Worker, written as an Effect program. It has no HTTP routes; it exposes RPC methods that return Effects.
- `src/` is the TanStack Start app. Routes live in `src/routes/` (file-based; `src/routeTree.gen.ts` is generated by the dev server and build, so don't edit it). Style with StyleX (`@stylexjs/stylex`). `src/index.css` holds only global resets; StyleX appends its CSS to it in builds.
- `src/server/` holds server functions (`createServerFn`). They call the API Worker with `toRpcAsync<typeof Api>(env.API)` from `@alchemy.run/cloudflare/Bridge`, with `env` from `cloudflare:workers`. Effect stays on the server: the browser imports only server function stubs, never `worker/` code. Tagged errors from the API Worker arrive as plain objects with a `_tag`.
- Each TypeScript area has its own tsconfig: `tsconfig.app.json` (`src/`, with Workers types because server functions live there), `tsconfig.worker.json` (Workers, `worker/`), `tsconfig.node.json` (config files).

## Commands

- `pnpm dev` runs `alchemy dev`. Both Workers run locally in workerd and the web app is served at http://localhost:5173.
- `pnpm alchemy deploy` deploys (stage `live_$USER` by default). Ask before deploying. `pnpm deploy` is a pnpm built-in, not this.
- `vp check` formats, lints, and type checks. Alchemy runs the Vite build with its Cloudflare plugin during dev and deploy; plain `vp build` fails on `cloudflare:workers`.
- Alchemy state lives in Cloudflare (`Cloudflare.state()`), so `alchemy dev` also needs Cloudflare credentials. Use `alchemy profile edit --add Cloudflare` locally, or `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` in CI and orbs.
- Alchemy docs index: https://alchemy.run/llms.txt

## Amp orbs

- `amp orb services ensure` starts `pnpm dev` with a per-thread stage and a portal on port 5173.
- `.agents/resume` sets `vm.overcommit_memory=1`. Without it, oxlint panics during `vp check` inside orbs.

# Using Vite+, the Unified Toolchain for the Web

This project is using Vite+, a unified toolchain built on top of Vite, Rolldown, Vitest, tsdown, Oxlint, Oxfmt, and Vite Task. Vite+ wraps runtime management, package management, and frontend tooling in a single global CLI called `vp`. Vite+ is distinct from Vite, and it invokes Vite through `vp dev` and `vp build`. Run `vp help` to print a list of commands and `vp <command> --help` for information about a specific command.

Docs are local at `node_modules/vite-plus/docs` or online at https://viteplus.dev/guide/.

## Built-in Commands vs Scripts

`vp <name>` runs a built-in command. `vp run <name>` runs a `package.json` script or a `vite.config.ts` task. Scripts cannot overwrite built-ins, so `vp dev` and `vp run dev` may do different things. Check `package.json` and `vite.config.ts` first, and run `vp run <name>` when the project defines a script or task with that name.

## Running Scripts

Run TypeScript and JavaScript files with `vpx <file>`, for example `vpx ./scripts/seed.ts --dry-run`. It handles enums, decorators, JSX, and tsconfig `paths`, so do not add `tsx` or `ts-node` to run scripts. `vpx --watch <file>` reruns the file when a file it uses changes, in place of `tsx watch`. `vp node <file>` runs plain Node.js.

## Tool Versions

Run `vp toolchain` to show versions and relationships in the active Vite+
release. Add a tool name to select part of the graph. For example, run
`vp toolchain vite`. Use `--global` to ignore the local `vite-plus` package. Use
`vp why <package>` to show the package-manager dependency graph.

## Review Checklist

- [ ] Run `vp install` after pulling remote changes and before getting started.
- [ ] Run `vp check` and `vp test` to format, lint, type check and test changes.
- [ ] Check if there are `vite.config.ts` tasks or `package.json` scripts necessary for validation, run via `vp run <script>`.
- [ ] If setup, runtime, or package-manager behavior looks wrong, run `vp env doctor` and include its output when asking for help.
